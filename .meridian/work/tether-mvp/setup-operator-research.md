# Tailscale Serve config writes by a Linux operator

**Scope checked:** Tailscale tag `v1.94.0` (commit `82077075c79f2c20bc663029dd14ab2f19e09307`) and `main` as fetched 2026-10-24 (commit `566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225`). Mainline references below are commit-pinned where useful; tag references use `v1.94.0`. Line references are to the pinned commits above.

## Bottom line

- **Serve config writes are allowed without root for the configured operator over the Unix LocalAPI socket.** Tailscale's `ipnserver` grants a Unix-socket actor `PermitWrite` when `ConnIdentity.IsReadonlyConn` says the peer is not read-only; the configured operator UID is explicitly read/write. The operator need not run the Tailscale CLI for ordinary Serve configs.
- **There is a version-specific catch for this exact `unix:` proxy target.** In `v1.94.0`, the extra “local admin” check applies only to path handlers, so a `unix:` proxy target is not blocked by it. In current `main`, the POST additionally checks configs that serve Unix sockets. A non-root operator then also has to pass `IsLocalAdmin`, which checks that `sudo --other-user=<user> --list tailscale` succeeds. Thus `--operator` alone is not enough for `unix:` on current main. This does not make the request itself require `sudo`; it does mean the operator setup must satisfy Tailscale's sudo-capability test.
- For a non-operator, `/serve-config` POST returns **403** with body `serve config denied\n`; this is the stable one-time hint trigger in Tailscale CLI (its 403 error is typed `AccessDeniedError`).

## 1. LocalAPI write permissions and operator grant

On both versions the LocalAPI server builds the handler from the connection actor and sets `PermitRead, PermitWrite = actor.Permissions(OperatorUserID())` (`ipn/ipnserver/server.go`, v1.94.0 [L210-L223](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/ipnserver/server.go#L210-L223); main [L210-L223](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/ipnserver/server.go#L210-L223)). For Unix sockets, `Permissions` returns `read=true` and write iff `IsReadonlyConn` is false (v1.94.0 [L336-L354](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/ipnserver/server.go#L336-L354); main same [L336-L354](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/ipnserver/server.go#L336-L354)). `IsReadonlyConn` explicitly recognizes the operator UID and returns read/write (v1.94.0 [L166-L207](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/ipnauth/ipnauth.go#L166-L207); main [L166-L207](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/ipnauth/ipnauth.go#L166-L207)). This is the newer `ipnauth.Actor` permission path, not an operator check in the Serve handler itself; the actor API docs describe operator UID as a Unix user allowed to use tailscaled without root/sudo ([actor.go L55-L64](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/ipnauth/actor.go#L55-L64)).

`POST /localapi/v0/serve-config` rejects if `PermitWrite` is false (v1.94.0 [serve.go L45-L49](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/localapi/serve.go#L45-L49); main [L45-L49](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/localapi/serve.go#L45-L49)). Therefore, for a normal Unix socket peer with matching operator UID, the permission check allows POST.

## 2. `unix:` proxy authorization and POST validation

### Version difference that matters to tether

- **v1.94.0:** the post-decode authorization check only applies when `configIn.HasPathHandler()`; configs without a path handler return from that check. A proxy handler with `Proxy: "unix:/…"` is not a path handler (`ipn/serve.go` [L234-L269](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/serve.go#L234-L269)), so tether's Unix-socket proxy is not specially root-gated on the serve-config POST path. The POST's Linux check and its exact error are at [localapi/serve.go L56-L108](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/localapi/serve.go#L56-L108).
- **current main:** the guard was broadened to `HasPathHandler() || IsServingUnixAny()`. Unix socket targets now trigger the local-admin check ([localapi/serve.go L56-L108](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/localapi/serve.go#L56-L108); `IsServingUnixAny` scans TCP/web/foreground handlers in [ipn/serve.go L272-L295](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/serve.go#L272-L295)). `IsLocalAdmin` accepts root, or a non-root configured operator only if `sudo --other-user=<username> --list tailscale` succeeds, with a 3-second timeout ([ipnserver/actor.go L210-L268](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/ipnserver/actor.go#L210-L268)). Otherwise the handler responds **401 Unauthorized**, body `must be root, or be an operator and able to run 'sudo tailscale' to serve a path or Unix socket\n`.

For context, the Unix socket scheme itself is an allowed target on Unix-like systems in CLI help ([serve_v2.go L139-L157](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/cmd/tailscale/cli/serve_v2.go#L139-L157)). CLI target expansion supports Unix where that target type permits it, but the LocalAPI POST does **not** itself parse and expand a target; it decodes JSON, runs authorization, checks ETag, then calls `SetServeConfig`. For v1.94.0 the backend rejects a missing netmap/self node, config-file-locked state, Funnel with shields-up, ETag mismatch, and incompatible config update before state-store write ([ipnlocal/serve.go L303-L365](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/ipnlocal/serve.go#L303-L365); current [L345-L400](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/ipnlocal/serve.go#L345-L400)). Config update validation covers incompatible TUN/handlers and listener conflicts/type changes (v1.94 [L1630-L1685](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/ipnlocal/serve.go#L1630-L1685); main [L1758-L1805](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/ipnlocal/serve.go#L1758-L1805)).

The Unix proxy runtime also requires a non-empty path and refuses proxying to tailscaled's own socket (v1.94 [ipnlocal/serve.go L806-L829](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/ipnlocal/serve.go#L806-L829); main [L887-L910](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/ipnlocal/serve.go#L887-L910)). The tailscaled process must be able to connect to the target socket; the POST does not verify the target exists/is connectable before accepting the config.

## 3. Reads: serve config and status

Yes. On the Unix-socket actor path `Permissions` always grants read access, even when write access is denied; `/serve-config` GET checks only `PermitRead` (v1.94 [localapi/serve.go L27-L44](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/localapi/serve.go#L27-L44); main [L27-L44](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/localapi/serve.go#L27-L44)). `/status` likewise checks `PermitRead` ([localapi.go L846-L859](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/localapi/localapi.go#L846-L859)). Thus tether can continue its current unprivileged GETs; the operator flag is relevant to write access, not needed for these reads (assuming the socket is reachable).

## 4. `tailscale serve` CLI and hint

With operator set, `tailscale serve` uses the same local client/serve-config endpoint as the direct API and succeeds without invoking `sudo` for normal (non-path, non-Unix-socket on current main) configs. The CLI prints an actionable hint on **403** access-denied errors: `Use 'sudo tailscale …'. To not require root, use 'sudo tailscale set --operator=$USER' once.` ([cli.go L167-L174](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/cmd/tailscale/cli/cli.go#L167-L174)); HTTP 403 is converted to `AccessDeniedError` ([client/local/local.go L186-L200](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/client/local/local.go#L186-L200)).

Important caveat: the current-main Unix local-admin guard returns **401**, and the LocalAPI client only translates 403/412 into special typed errors (same client lines). Therefore that Unix-specific 401 does **not** trigger the generic CLI `--operator` hint. The error itself says that sudo-capable operator access is required. In v1.94 Unix proxy configs avoid that guard, so the usual 403 operator hint applies only if the user is not an operator.

## 5. Funnel, HTTPS cert availability, and cert detection

- **Funnel:** not required to publish ordinary private Serve. The CLI's Funnel command calls `verifyFunnelEnabled`, which checks HTTPS+Funnel node capabilities and port allowance ([funnel.go L129-L161](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/cmd/tailscale/cli/funnel.go#L129-L161)); ordinary Serve does not do this. Funnel capability/attributes affect public Funnel, not a plain HTTPS Serve listener.
- **Tailnet HTTPS certificate setting:** `serve-config` POST does not provision a certificate or gate the write on certificate availability. Read `Status.CertDomains`; it is documented as DNS names for which control plane assists in TLS certificate provisioning ([ipnstate/ipnstate.go L70-L75](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/ipnstate/ipnstate.go#L70-L75)), or GET `/localapi/v0/cert-domains`, which returns `DNS.CertDomains` (empty if no netmap yet) and requires only read access ([localapi.go L1109-L1124](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/localapi/localapi.go#L1109-L1124)). **An empty list means no certificate domain is currently advertised**; it can mean HTTPS certs aren't enabled/configured, but also the node has not received a netmap yet, so distinguish those cases before claiming tailnet setting is disabled. A client should check `Self`/connected status and then `CertDomains`, and give the HTTPS-setting guidance if connected but the list is empty. The CLI's Funnel fallback emits `Funnel not available; HTTPS must be enabled. See https://tailscale.com/s/https.` for absent HTTPS capability (test cases [serve_legacy_test.go L810-L830](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/cmd/tailscale/cli/serve_legacy_test.go#L810-L830)).
- A cert acquisition attempt uses LocalAPI `/cert/<domain>` and returns a domain-specific error/status if unavailable ([localapi/cert.go L20-L57](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/localapi/cert.go#L20-L57)). A config write succeeding therefore doesn't prove cert provisioning will work.

## 6. Non-operator POST response and hint recognition

Both versions' handler returns `http.Error(w, "serve config denied", 403)` immediately when `PermitWrite` is false (v1.94 [serve.go L45-L49](https://github.com/tailscale/tailscale/blob/v1.94.0/ipn/localapi/serve.go#L45-L49); main same [L45-L49](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/localapi/serve.go#L45-L49)). Go `http.Error` appends newline: body is `serve config denied\n`. The LocalAPI client converts HTTP 403 body to `AccessDeniedError` ([client/local/local.go L186-L200](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/client/local/local.go#L186-L200)); the CLI then prints the `sudo tailscale set --operator=$USER` hint (above). For tether, match the status **and** endpoint/body, rather than relying on broad text matching: 403 is the unambiguous permission-denied path; current-main Unix-special-case 401 is distinct.

## Other setup considerations

- Use the LocalAPI ETag as tether already does: GET returns an ETag and POST's `If-Match` is checked as optimistic concurrency control (main [localapi/serve.go L32-L44, L65-L72](https://github.com/tailscale/tailscale/blob/566f89e0fb2aa4b2f1ebf98761e45e62aa5ef225/ipn/localapi/serve.go#L32-L44)). A 412 means another writer changed the config; re-GET/merge/retry rather than overwrite.
- `tailscaled` must be running and have a self netmap, and it must not be using a locked config file. A not-yet-connected machine can therefore deny write independent of operator access.
- Current-main validation has tightened since v1.94 for Unix targets; tether needs to account for deployed Tailscale version and/or explain the requirement before writing. This is the major compatibility caveat for the planned Linux `unix:/run/user/<uid>/tether/serve.sock` target.

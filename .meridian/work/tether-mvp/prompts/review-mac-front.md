Review a security design before it is built: tether's Mac front (docs only, uncommitted; `git diff` in /Users/jimmyyao/repos/tether shows it).

tether is a Rust daemon that is remote code execution for whoever passes its auth. On Linux, Tailscale Serve reaches it through `serve.sock` in a 0700 dir. On a Mac, the Tailscale app's sandboxed root extension can't connect to Unix sockets and an unprivileged daemon can't learn a loopback TCP peer's process, so Jimmy chose: loopback TCP front + a random path secret Serve adds to every request (tether writes its own Serve config through LocalAPI and rotates the secret each start) + a Host rule, then the existing Tailscale check and lanes. Documented as weaker than Linux, Mac with Jimmy as only admin.

Read: docs/design/auth.md (Overview, Threat model, "Reaching LocalAPI" under Sockets, "The Mac front", Canonical origin, Endpoints, Module shape, probe gates M1–M8, Open risks); docs/design/decisions.md (the new "A Mac can host tether" entry and "## The Mac front" at the end); docs/running.md "Host on a Mac"; docs/design/plan.md server platform; the build order in .meridian/work/tether-mvp/mac-front-design.md.

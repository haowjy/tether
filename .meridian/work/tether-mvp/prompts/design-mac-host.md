# Design: tether hosted on a Mac running the Tailscale app

Jimmy chose (2026-10-24) to support his Mac as a tether host with the Tailscale app as installed, over switching to Homebrew tailscaled or staying Linux-only, knowing it is "a real auth redesign". Produce the design: revise `docs/design/auth.md` (and `docs/running.md`, `docs/design/plan.md` where they say Linux-only) to state the new rule, and log the decision with rejected alternatives in `docs/design/decisions.md`. Docs only; no code. A reviewer checks it before anyone builds it.

Evidence (read first): `.meridian/work/tether-mvp/mac-host-investigation.md` (p168 plus the lead's follow-up), `.meridian/work/tether-mvp/serve-mac-probe.md` (p125), `src/auth/` (`identity.rs`, `mod.rs`, `node.rs`), `src/http/` (`mod.rs`, `server.rs`), `src/runtime.rs`, and auth.md whole — especially the canonical-origin rule and why a TCP forward was rejected (`auth.md` ~238–280), and the probe gates G1–G12.
Facts established on this Mac (Tailscale 1.104.2, macsys/system-extension variant; the App Store variant differs):
- LocalAPI: loopback TCP, port from `/Library/Tailscale/ipnport`, token in `/Library/Tailscale/sameuserproof-<port>` (root:admin 0640), HTTP Basic auth; whois/status/serve-config all work. App Store variant: `lsof` discovery of `sameuserproof-<port>-<token>` held by `IPNExtension` (upstream `safesocket_darwin.go` v1.104.2).
- Serve forwards to loopback TCP (200) but reaches no Unix socket we tried (502, zero accepts), consistent with the extension's sandbox.
Requirements: the iPhone app (token lane) and the phone browser/PWA (node lane) both work against a Mac host; Linux keeps its Unix-socket model unchanged; no weaker guarantee on Linux; principles in AGENTS.md (private, tailnet only, never Funnel; light; tmux is the source of truth).
The design must answer, with a threat model: who can reach a loopback TCP front (other local users; processes running as Jimmy, including sandboxed apps; web pages in any local browser via cross-origin requests or DNS rebinding; other tailnet nodes) and what each can forge (Host, X-Forwarded-For, Tailscale-User-Login, Origin). **Jimmy's call (2026-10-24):** the Mac front's trust rests on peer-process provenance (option 2 below): every TCP connection must be verified to come from Tailscale's root-owned, Tailscale-signed extension process, so no other local process or user can talk to the front at all. Design the refactor for it: the auth code gets an explicit front type that carries its trust rule (Unix Serve socket: as today; Mac TCP front: peer verified first), and an explicit LocalAPI transport. Layer the secret prefix and strict Host rule on top only if they add defence the peer check doesn't; say which. If peer provenance proves infeasible on this Mac (POC it early), stop and report before writing the rest.
Evaluate at least:
1. A secret path prefix in the Serve target (`tailscale serve http://127.0.0.1:PORT/<secret>`): does Serve forward the prefix on every request including WebSocket upgrades, who can read the Serve config (and so the secret), rotation, what it defends (rebinding/CSRF) and what it doesn't (local users who can read serve-config).
2. Peer-process provenance: per TCP connection, verify the connecting socket belongs to Tailscale's root-owned, Tailscale-signed extension process (macOS APIs to map a loopback TCP peer to a pid: `proc_pidfdinfo`/`libproc`, sysctl `net.inet.tcp.pcblist_n`; cost per connection; works with Serve's connection pooling?).
3. Requiring whois on the forwarded address alone (p168: insufficient, forgeable) — state why rejected.
4. A strict Host/origin rule against DNS rebinding.
Pick the combination; say what the Mac host trusts that Linux doesn't, and whether that is acceptable for a single-user Mac (a process running as Jimmy can already `tmux attach`). Specify: the LocalAPI transport selection (Linux socket paths, macsys proof file, App Store lsof) and its failure behaviour (not a startup gate); the front's listener and the publish command `running.md` gives; how canonical origin (G7) classifies a TCP target with the secret; which probe gates change and the new Mac gates. Small POCs are allowed under /tmp/tether-meridian-501/macdesign-<spawn id>/ to settle a fact (e.g. whether Serve keeps the path prefix on a WebSocket upgrade, or how to read a loopback peer's pid) — reset `tailscale serve` after and kill what you start; no Funnel; isolated `tmux -L` only. Don't commit; report the recommendation, the doc diffs, and open questions for Jimmy.

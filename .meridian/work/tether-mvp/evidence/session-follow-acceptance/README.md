# Session-follow runtime acceptance (p249)

**Scope/run mode.** Manual runtime probe, not an automated suite. No production or test source edited and no suite run. Served the current web source via the disposable `web/e2e/shared/stack.ts`-style Vite/dev-proxy harness and `target/debug/tether`; each daemon used its own private tmux socket, runtime/state/home/config, ports, browser session and controlled `sh` pane contents. Tmux binaries: `~/.cache/tether-tmux/3.4/bin/tmux` and `~/.cache/tether-tmux/3.7b/bin/tmux`. Browser viewport was 2000×970 CSS px; phone views used a Playwright iPhone 14 context (390×844 CSS px, DPR 3, touch/coarse pointer), not a physical device. No manual `resize-window`/window-size command was used; laptop sizes came from real `script` PTYs.

## Representative reproduction details

- Browser: `agent-browser set viewport 2000 970`; open `follow-a` from Home. Check actual size with the private tmux binary: `tmux -L <socket> list-windows -t follow-a -F '#{window_name}:#{window_width}x#{window_height}:#{window_active}'`. At browser ownership the shown window was `term-b:274x53:1`.
- Attach laptop: private harness `stack.attach("follow-a", {cols: 80, rows: 24})`, then type `printf "LAPTOP_TYPED_MARKER\\n"` plus Return (or `LARGE_LAPTOP_MARKER` from a 320×80 PTY). The command actually appeared in `tmux capture-pane -p -t follow-a:term-b`; active window dimensions changed to 80×23 / 320×79. Wait ~2 seconds, then click Fit and query `list-windows` again; it returned to 274×53.
- Prefix-n: send Ctrl-B then `n` through the PTY. `tmux display-message -p -t follow-a '#{window_index}:#{window_name}:#{window_width}x#{window_height}'` and the tab's accessible name both changed to the new current window.
- Disconnection: private harness dropped the one `/ws` socket (`curl -X POST http://127.0.0.1:<private-control-port>/drop` returned `1`); with browser network offline, terminal input received `echo OFFLINE_RAW_MARKER` and Return. After network restoration/reconnect, `tmux capture-pane -p -S -30 -t follow-a:term-b | grep OFFLINE_RAW_MARKER` produced no match.
- Phone: opened the real Home session row, then the dock's active-tab chip; screenshots were captured at the emulated 390×844 viewport. The multi-window view had two rows and New window; the one-window view had New window and no window rows. Both had `document.documentElement.scrollWidth === innerWidth === 390`.

## Device and incidental observations

- Real iPhone keyboard/viewport/Face ID and native-app checks are **not covered**; Playwright and browser emulation cannot certify them.
- The one-window phone sheet's session list scrolls behind the fixed bottom search/New session row; at the 390×844 viewport the lowest session row is partly below that bar until scrolled. This looked like expected scroll containment, not a proven defect.
- No other issue was reproduced. No release, push, personal tmux socket, shared stack restart, or persistent test was used.

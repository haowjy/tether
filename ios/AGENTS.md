# ios/

The native iPhone shell. It hosts the bundled web UI in a WKWebView and owns what the
web can't: the terminal input's first responder, keyboard geometry, the Face ID-locked
device token, haptics, lifecycle and media. It draws nothing above the keyboard; the
phone dock is web. Spec: [ios-shell.md](../docs/design/ios-shell.md).

- **One focus owner.** `Input/FocusController.swift` is the only code that makes
  `KeyboardInput` first responder or resigns it; native code and the web (over the
  bridge) ask it for a mode. Its modes and transitions are in ios-shell.md, "Focus: one
  controller, native"; a second caller puts the keyboard in a state none of them
  describes. One native text field owns both the terminal and line targets.
- **Add server is native.** Manual enrolment and the browser's `tether://add` handoff
  use the same two-step host/code then device-name form; a link prefills its host and
  optional code but never enrols until Next and Add are tapped. With a code, Add first
  enrols the phone's node and then mints its native token; one code also admits Safari
  and the PWA on that phone. Empty code keeps the single node-mint path. The full input
  and failure rules are in ios-shell.md, "Hosts".
- **The bridge v5 contract has one copy:** the fixtures in `TetherKit/Tests/Fixtures/bridge/`.
  The Swift DTOs and `web/platform/native/` both decode them, so a message change
  edits all three in one commit.
- **`project.yml` is the project.** `Tether.xcodeproj` is generated by XcodeGen and
  ignored; never hand-edit `project.pbxproj`. The signing team stays unset in the repo;
  Jimmy picks it in Xcode.
- **Builds and tests run on the Mac:** `ios/scripts/check.sh` (XcodeGen, `swift test`,
  a Simulator build). Preflight doesn't build iOS.
- **Installing on the phone:** build for the device with the team on the command line,
  then install the Release app. `DQK9XRFMG4` in `security find-identity` is a
  certificate ID, not a team: using it fails with "No Account for Team". The team Xcode
  is signed into is `D4K9ZT557F`.

  ```bash
  cd ios && xcodegen generate --spec project.yml
  xcodebuild -project Tether.xcodeproj -scheme Tether -configuration Release \
    -destination "id=<phone udid>" -derivedDataPath "$TMPDIR/tether-ios-device" \
    -allowProvisioningUpdates DEVELOPMENT_TEAM=D4K9ZT557F CODE_SIGN_STYLE=Automatic build
  xcrun devicectl device install app --device <phone udid> \
    "$TMPDIR/tether-ios-device/Build/Products/Release-iphoneos/tether.app"
  ```
- **The Simulator can't verify input.** From an agent shell it shows no software
  keyboard, and `simctl` can't tap or type. Keyboard, focus, geometry and rotation are
  verified only by the device checklist in ios-shell.md, which Jimmy runs on his
  iPhone. A change to any of them is Simulator-built and device-unverified until then;
  say so in your report.

# ios/

The native iPhone shell. It hosts the bundled web UI in a WKWebView and owns what the
web can't: the terminal input's first responder, keyboard geometry, the Face ID-locked
device token, haptics, lifecycle and media. It draws nothing above the keyboard; the
phone dock is web. Spec: [ios-shell.md](../docs/design/ios-shell.md).

- **One focus owner.** `Input/FocusController.swift` is the only code that makes
  `TerminalInputView` first responder or resigns it; native code and the web (over the
  bridge) ask it for a mode. Its four modes and their transitions are in ios-shell.md,
  "Focus: one controller, native"; a second caller puts the keyboard in a state none of
  them describes.
- **The bridge contract has one copy:** the fixtures in `TetherKit/Tests/Fixtures/bridge/`.
  The Swift DTOs and `web/platform/native/` both decode them, so a message change
  edits all three in one commit.
- **`project.yml` is the project.** `Tether.xcodeproj` is generated by XcodeGen and
  ignored; never hand-edit `project.pbxproj`. The signing team stays unset in the repo;
  Jimmy picks it in Xcode.
- **Builds and tests run on the Mac:** `ios/scripts/check.sh` (XcodeGen, `swift test`,
  a Simulator build). Preflight doesn't build iOS.
- **The Simulator can't verify input.** From an agent shell it shows no software
  keyboard, and `simctl` can't tap or type. Keyboard, focus, geometry and rotation are
  verified only by the device checklist in ios-shell.md, which Jimmy runs on his
  iPhone. A change to any of them is Simulator-built and device-unverified until then;
  say so in your report.

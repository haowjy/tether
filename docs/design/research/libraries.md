### Terminal-emulation conclusion

Keep the plan's **`vt100` → fixture-driven fallback to `alacritty_terminal`**. Do
not change to Ghostty merely because Ghostty has excellent Unicode behavior; the
browser can be evaluated separately with `ghostty-web`. There is no official,
stable Rust binding to libghostty-vt that is a better server dependency today.

## Recommended picks

1. **Server:** Tokio current-thread + **axum 0.8.9** + **tower-http 0.7.1**; use `rust-embed 8.13.0` for the PWA. Keep custom file-serving code for rooted authorization and streamed/range media.
2. **Auth:** Add **webauthn-rs 0.5.5** explicitly and pair it with **`@simplewebauthn/browser` 14.x**. Do an iPhone Safari passkey spike before treating Face ID as done. Implement a small private Tailscale LocalAPI client over Unix-socket Hyper unless `tslocal` passes an endpoint/socket compatibility spike; do not make a low-signal wrapper an auth boundary.
3. **Observability/service:** `tracing` + `tracing-subscriber`, optional `tracing-journald`, and `sd-notify`. Journald is an output layer, not the only logger.
4. **Protocol types:** **ts-rs** for the current WebSocket/JSON DTO set. Switch to typeshare only if a native Swift client becomes a real deliverable; do not use specta for plain DTO generation.
5. **tmux:** Keep the **hand-written parser** as the production boundary, but run a spike against `tmuxctl` and `libtmux`. If either proves complete for `%output`, `%begin/%end`, `pause-after`, and window/session events on tmux 3.4 and 3.7b, adopt only its parser layer—not a broad session-management abstraction.
6. **Screen model:** **vt100 0.18.1** first, with golden fixtures and a measured fallback to `alacritty_terminal 0.26.0`. Do not use `wezterm-term` or Ghostty Rust bindings in the daemon yet.
7. **Browser:** **xterm.js 6.0 + WebGL with DOM fallback + serialize + search + web-links**, one Unicode addon selected by device fixtures, and the custom touch/selection/input-sink work already called out in the plan. Keep `ghostty-web 0.4.0` as a bounded renderer experiment, not a rewrite prerequisite.
8. **App shell:** **Preact 11.0.1** for the small PWA unless the implementer is already materially faster in Svelte 5.
9. **File content:** `markdown-it 15.0.2` + **DOMPurify 3.4.17**; **Shiki 4.5.0** dynamically loaded with a language allowlist (use highlight.js 11.12.0 if bundle/startup measurements make Shiki too costly); Mermaid 12.2.0 is a lazy, strict-mode extra.
10. **Completion:** Keep **carapace-bin 1.8.0**, but pin and treat export JSON as a tolerant, tested integration rather than a stable schema.

## Plan choices to change

- **Name the auth libraries.** Replace the generic “webauthn” plan entry with `webauthn-rs 0.5.5` + `@simplewebauthn/browser 14.x`, MPL-2.0 review, exact-origin/RP-ID tests, and an iOS Safari/WKWebView acceptance test.
- **Change the LocalAPI decision from “find a client” to “own a narrow adapter.”** First try plain Hyper over the tailscaled Unix socket; use `tslocal` or `tailscale-localapi` only if a compatibility spike shows they materially reduce code without hiding errors. This keeps Tailscale presence detection replaceable and auditable.
- **Keep `rust-embed`; do not switch to `include_dir`.** Evaluate `memory-serve` only if its automatic ETag/cache/compression behavior beats the measured binary/RSS cost. It is not a reason to change the architecture.
- **Retain the vt100-first ladder.** The recent vt100 releases are healthy enough to try, but the sudden release burst means fixture tests are mandatory. `alacritty_terminal` remains a fallback, not a second simultaneous screen model.
- **Do not adopt Ghostty Rust bindings for the server.** Their current value is a future client/rendering experiment; unstable bindings, Zig builds, and thread-safety/build provenance are a poor fit for the daemon's first release.
- **Keep xterm.js for MVP, but make the renderer replaceable.** Ghostty-web is credible and has a much better Unicode story, yet its 0.x status and missing xterm addon parity make it a spike, not a plan replacement. Test iPhone Safari WebGL context loss, WASM startup, selection, clipboard, resize, and suspend/resume before deciding.
- **Make the Markdown/diagram security boundary explicit.** Add DOMPurify and strict URL/HTML policy to §8; Mermaid must be lazy and `securityLevel: "strict"`, never implicitly trusted because it came from a Markdown file.
- **Change syntax-highlighting wording from “choose a library” to “lazy, allowlisted language chunks.”** Pick Shiki first for fidelity, with highlight.js as the measured fallback; do not import all languages or Prism by default.
- **Correct the Carapace assumption.** Keep the binary, but remove any implication that “1000+ tools” or the export JSON shape is stable. Pin the binary, parse forward-compatibly, keep golden fixtures, and make completion opportunistic.
- **Add a tmux parser spike gate.** The hand-written parser is still reasonable, but `tmuxctl` and `libtmux` now exist as credible references. The gate should compare correctness and dependency cost on both tmux versions before implementation commits to either hand-written or third-party parsing.
